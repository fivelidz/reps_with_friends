## Shipped

**`packages/bot-core/src/sot-bus.ts`** — `SotCommandBus` + `SotStore`, PARALLEL
to the legacy `CommandBus`/`MatchStore` (zero shared state; legacy v1–v3 bots
untouched and still green). The SOT grammar:

- `new [target]` — group + weekly season scaffold. Defaults: **200 adjusted**,
  active days Mon–Fri, tier handicap, creator auto-in as casual (re-tier via
  `join`). Card prints the tier→physical-target table (couch 134 / casual 160 /
  fit 200 / athlete 236).
- `join [tier]` — physical-target card per joiner; re-tiers between days;
  mid-day joins are held for the next day (engine days snapshot their roster).
- `start` — opens the day (`createDay`), ≥2 players, play-day check, deadline
  = next 21:00 local (or `dayWindowMs` opt), deals the **prototype power-up
  kit** (one canon card of each per player per day — real economy is Q240-242,
  our draft-from-3 answer stays live in v1–v3).
- `log <ex> <reps>[!]` — engine `logSet` applies the tier multiplier; reply =
  banked reps + remaining-to-target + position. **On first-to-target: the
  DAILY WIN moment card** ("the battle continues — bank your day"); later
  completions get the **banked-day card** (streak projection, "the point was
  already taken").
- `s` / `standings` — per-player target status (🏆 WON / 🏦 BANKED / % /
  failing-if-it-holds) + season points + streaks.
- `day close` — recap (winner, banked, failed, shielded, streaks) via
  `closeDay` → `dayRecordFrom` → `recordBattleDay`. Refuses before the
  deadline (`day close force` = ops/demo, settles at deadline terms). **Auto-
  closes at the deadline**: the recap is prepended to the next reply.
- `season` / `season ladder` / `season end` — weekly standings 1:1 (1 Daily
  Win = 1 point); `season end` locks the season + resolves the stake.
- `stake <type> <terms>` + `agree` / `decline` — full lifecycle:
  dinner/dare/deliverable/charity, agreement-gated (active only when ALL
  accept, decline → void), resolves at season end (winner = most wins,
  bottom-tie = joint losers owe). `stake done [note]` = fulfilment; `stake`
  bare = status (works after resolution too).
- `pot <points>` / `pot` — charity contributions in POINTS (trial currency),
  sealed until the stake is active. `charity <name>` (winner-only) →
  `donate` (pot − disclosed fee; 0% trial).
- Power-ups, SOT canon: `lightning` (×3/10min), `steal @name` (**pure gain —
  "you GAIN X, they keep theirs"**, does NOT count toward the target),
  `shield` (group streak protection, consumed at the close it saves),
  `freeze` (+30 min group-wide), `bomb @name` (+20/10min, defusal bonus),
  `rope @name` (50-credit to an inactive mate). `cards` shows the hand.
- `help` — the grammar in SOT language: reps, Daily Win, bank your day.

## Gotchas hit

- Bun doesn't typecheck: a bad method reference (`sotLadderCardIfAny` vs
  `this.ladderCardIfAny`) only surfaced at runtime — run the sims, not just
  the tests, before claiming a bus change works.
- The engine's activation order checks "no card held" BEFORE daily limits —
  a second `steal` reports the kit, not the limit. Tests assert the real
  message.
- `freeze` moves the effective deadline, so tests/sims that close "past the
  deadline" must account for +30 min (one test advances 6h31m for exactly
  this — it doubles as freeze verification).
- DayRecords key on ISO date: two `start`→close cycles on the SAME date hit
  `recordBattleDay`'s duplicate-date throw. The bus catches it and notes
  "season bookkeeping skipped" on the recap rather than breaking the close.
- `resolveTarget` matches roster names by substring either direction after
  stripping `@` — same loose style as the legacy `taunt`; empty post-strip
  tokens are rejected so `steal @` can't match an arbitrary player.
- Sim clock base rewinds Fri/Sat/Sun → Thursday so day 2 (Friday) is a play
  day; without that, weekend demos die on the Mon–Fri play-day check.
