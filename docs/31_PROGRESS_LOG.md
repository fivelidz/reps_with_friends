## 2026-09-10 — OFFLINE CARD QUEUE (cloud groups): power-ups queue like logs

**Shipped:** the founder expectation — "people can still log reps but get the powerup impacts when they reconnect" — closed the gap where a card play offline in a CLOUD group just errored. **Conn shim now carries two kinds of queued item**: `kind:"log"` (sets, as before) and `kind:"cmd"` (`{id, clientCmdId, text, label, code}` — the exact chat command the bots send, minted by the same crypto generator as log ids; legacy entries read as logs). **Card-play path** (confirmCard Confirm): offline × cloud group → `Conn.enqueueCmd(cardCmdText(...))` → a queued-card variant of the queued-set sheet ("QUEUED — PLAYS WHEN YOU RECONNECT", queue chips, remove-from-queue) — and the card stays **UNPLAYED locally** (no optimistic local effect: the server is the authority and a local effect the server never saw would be wiped by the next poll merge). **Replay** (`replayQueuedLogs`, two-pass: logs first, then cmds): cmds replay through `RWFCloud.cmd(groupId, text, clientCmdId)` — now idempotent via a caller-supplied id (duplicate retry → server answers "Already handled") — against the crew the cmd was queued FOR (`code` field, not whatever group is active).
